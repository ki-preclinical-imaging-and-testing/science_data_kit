# Map Feature Guide

## Overview

The Map feature in Science Data Kit (SDK) allows you to define entities and relationships to create knowledge graphs. This guide explains how to use the Map page to load entities, define their structure and properties, create relationships between them, and build taxonomies and ontologies.

## Entity Management

### Loading Entities

You can load entities into the Map feature from various sources:

1. **From Files**:
   - Click the "Load from Files" button
   - Select the file containing entity definitions (CSV, JSON, or Excel formats)
   - Map the columns to entity properties
   - Click "Import" to load the entities

2. **From Database**:
   - Click the "Load from Database" button
   - Select the database connection
   - Choose the entities to load
   - Click "Import" to load the entities

3. **From Survey Results**:
   - If you've previously used the Survey feature, click "Load from Survey"
   - Select the survey results to use
   - Click "Import" to load the entities

### Creating Entities Manually

To create entities manually:

1. Click the "Create Entity" button
2. Enter a name for the entity
3. Select an entity type (or create a new one)
4. Add properties to the entity (name-value pairs)
5. Click "Save" to create the entity

### Editing Entities

To edit an existing entity:

1. Select the entity in the entity list
2. Modify the entity properties in the edit panel
3. Click "Save" to update the entity

### Organizing Entities

You can organize entities into groups:

1. Select multiple entities
2. Click "Group" to create a new group
3. Enter a name for the group
4. Click "Save" to create the group

## Relationship Management

### Creating Relationships

To create relationships between entities:

1. Select the source entity
2. Click "Create Relationship"
3. Select the target entity
4. Choose a relationship type (or create a new one)
5. Add properties to the relationship (optional)
6. Click "Save" to create the relationship

### Editing Relationships

To edit an existing relationship:

1. Select the relationship in the relationship list
2. Modify the relationship properties in the edit panel
3. Click "Save" to update the relationship

### Relationship Types

SDK provides several predefined relationship types:

- **IS_A**: Indicates that one entity is a type of another
- **PART_OF**: Indicates that one entity is part of another
- **RELATED_TO**: Indicates a general relationship between entities
- **DERIVED_FROM**: Indicates that one entity is derived from another
- **GENERATED_BY**: Indicates that one entity was generated by another

You can also create custom relationship types:

1. Click "Manage Relationship Types"
2. Click "Create New Type"
3. Enter a name and description for the type
4. Click "Save" to create the type

## Ontology Management

### Working with Taxonomies

A taxonomy is a hierarchical classification system. To create a taxonomy:

1. Click "Create Taxonomy"
2. Enter a name for the taxonomy
3. Add top-level categories
4. Add subcategories to each category
5. Click "Save" to create the taxonomy

### Working with Ontologies

An ontology is a more complex knowledge representation that includes entities, relationships, and rules. To create an ontology:

1. Click "Create Ontology"
2. Enter a name for the ontology
3. Define the entities and their properties
4. Define the relationships between entities
5. Define rules and constraints (optional)
6. Click "Save" to create the ontology

### Importing Existing Ontologies

You can import existing ontologies in standard formats:

1. Click "Import Ontology"
2. Select the ontology file (OWL, RDF, or OBO formats)
3. Map the ontology elements to SDK concepts
4. Click "Import" to load the ontology

### Exporting Ontologies

To export an ontology:

1. Select the ontology in the ontology list
2. Click "Export"
3. Choose the export format (OWL, RDF, or OBO)
4. Click "Export" to save the ontology file

## Visualization

### Entity Visualization

The Map feature provides several ways to visualize entities:

1. **List View**: Shows entities in a hierarchical list
2. **Graph View**: Shows entities and relationships as a network graph
3. **Tree View**: Shows entities in a tree structure based on IS_A relationships

To switch between views:

1. Click the view selector in the toolbar
2. Select the desired view

### Customizing Visualization

You can customize the visualization:

1. **Colors**: Assign colors to entity types
2. **Sizes**: Adjust the size of entities based on properties
3. **Layout**: Choose different layout algorithms for the graph view
4. **Filters**: Filter entities and relationships based on types or properties

## Saving and Loading Maps

### Saving Maps

To save your map:

1. Click "Save Map"
2. Enter a name for the map
3. Click "Save" to store the map

### Loading Maps

To load a previously saved map:

1. Click "Load Map"
2. Select the map from the list
3. Click "Load" to open the map

## Integration with Neo4j

### Pushing to Neo4j

To push your map to Neo4j:

1. Click "Push to Neo4j"
2. Configure the push settings:
   - **Node Labels**: How entity types map to Neo4j node labels
   - **Relationship Types**: How relationship types map to Neo4j relationship types
   - **Properties**: Which properties to include
   - **Merge Strategy**: How to handle existing data
3. Click "Push" to send the data to Neo4j

### Pulling from Neo4j

To pull data from Neo4j into your map:

1. Click "Pull from Neo4j"
2. Enter a Cypher query to select the data
3. Configure the import settings
4. Click "Pull" to import the data

## Troubleshooting

### Common Issues

1. **Entity creation fails**:
   - Ensure all required properties are provided
   - Check for duplicate entity names
   - Verify that the entity type is valid

2. **Relationship creation fails**:
   - Ensure both source and target entities exist
   - Check that the relationship type is valid
   - Verify that the relationship is allowed between the entity types

3. **Ontology import fails**:
   - Check that the file format is supported
   - Ensure the file is well-formed
   - Try simplifying the ontology if it's very large or complex

## Best Practices

1. **Start Simple**:
   - Begin with a small set of core entities and relationships
   - Expand gradually as your understanding of the domain grows

2. **Use Consistent Naming**:
   - Adopt a consistent naming convention for entities and relationships
   - Use clear, descriptive names that reflect the domain concepts

3. **Leverage Existing Standards**:
   - Where possible, align your ontology with existing domain standards
   - Reuse established taxonomies and ontologies rather than creating from scratch

4. **Document Your Design**:
   - Add descriptions to entities, relationships, and properties
   - Document the rationale behind your ontology design decisions
